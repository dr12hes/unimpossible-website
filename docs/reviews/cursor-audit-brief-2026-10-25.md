Smallest COMPLETE product first, not a homepage-only demo. Start on our own site; customer rollout and Wix later. Preserve existing features. He asked for cited proof/best practice; no authoritative basis for this cooldown was established. Do not treat our old docs/tests as user approval.

## Retro findings to independently investigate

1. Implementation shortcuts became product policy without discussion: weekly per-page cooldown, one-day recommendation publishing age, seven-day AI evidence age, two-day audit age, 50-URL cap, 40 eligible text fragments, truncation, description/text length caps, two recommendation categories with one edit each, only WordPress pages editable, narrow HTML text edits, two permitted Google source IDs. Classify each as security/correctness, resource bound, compatibility limitation, product policy or incomplete feature. Quantify actual effect and distinguish explicitly authorised scope from inferred scope. Inspect other consequential limits too.
2. Smallest scope became incomplete scope; repeated homepage/description slices did not demonstrate the broader customer outcome. Review the whole chain, including unsupported changes and what happens when useful work cannot be expressed.
3. Tests enforced invented rules rather than justified requirements. Distinguish useful regression tests from implementation-mirroring tests and pre-existing Core gates. Recommend smallest adequate verification; do not prescribe another framework or blanket deletion of security checks.
4. Evidence checks cover finding references, but a factual summary can bypass those checks. The real model returned findings=[] with a broad summary about historical Google AI Mode samples; independent review accepted it. Assess source binding, summary/reviewer quality, truncation, factual claims, stale evidence, and whether rejected/failed evidence can influence publishing.
5. Late real-model validation caused another full release. Long merge/design/release gates amplified a small change. Separate agent decisions from existing repository requirements; inspect whether focused validation/reuse already exists before suggesting new tooling.
6. Repeated status polling, near-complete claims, ad-hoc scripts and overlapping status documents obscured what was working versus unproven. Ponytail instructions did not reliably alter behaviour. Core AGENTS.md is 460 lines. Recommend targeted navigation/reviewer/process changes, not another stack of rules.
